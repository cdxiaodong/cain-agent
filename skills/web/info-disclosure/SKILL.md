# 敏感信息泄露漏洞检测技能

## 触发条件

仅在授权响应、错误页或公开静态路径出现非公开信息线索时启用本技能。

## 原理

敏感信息泄露发生在 Web 应用在响应、错误页面、注释、配置文件中暴露了不应公开的信息，攻击者可利用这些信息进行进一步攻击。

**常见泄露点**：
- 错误堆栈（stack trace 暴露路径/框架版本/SQL 语句）
- 备份文件（`.bak` `.swp` `.old` `~`）
- 版本控制目录（`.git/` `.svn/`）
- 配置文件（`.env` `config.php` `web.config`）
- 注释中的硬编码凭证 / 内网 IP / 测试账号
- HTTP 响应头（`Server` `X-Powered-By` 暴露版本）

## 三层测试模型

> 对齐 DESIGN §3.1：L1 探测 → L2 验证 → L3 绕过，每层只做上一层成立后才推进的事。

### L1 探测

目标：低成本扫一遍常见暴露面，标出候选线索，不下结论。

- 错误触发信号：对参数传入类型错误/超长值/特殊字符，检查响应是否包含 stack trace、SQL 语句片段、文件系统路径。
- 公开路径巡检：`.git/HEAD`、`.env`、`/actuator/env`、`/swagger.json`、`web.config.bak` 等已知敏感文件路径，只做单次存在性探测（状态码 + Content-Type），不下载内容。
- 响应头巡检：`Server` / `X-Powered-By` / `X-AspNet-Version` 等版本泄露头。

> L1 产出「候选泄露点 + 类型假设」，写入 `hypothesis`，不直接下结论。

### L2 验证

目标：确认候选线索确实构成「非公开信息」而非无害的公开元数据。

- 内容性质判定：区分「泄露的是版本号/框架名（低风险）」与「泄露的是凭证/内网地址/源码逻辑（高风险)」——只有后者才继续按更高定级处理。
- 重复验证：同一路径/参数重复请求（≥3 次）确认信息稳定可获取，而非一次性的调试残留（如恰好命中的临时日志）。
- 范围确认：确认该信息在未授权/低权限身份下即可获取（若需已登录高权限身份，则属于访问控制问题而非信息泄露）。

### L3 绕过

目标：当直接访问被拦截（404/403）时，验证是否仍可通过变形绕过发现。

- 路径变形：大小写、`/./`、`//`、URL 编码（`%2e%67%69%74`）、末尾追加 `?`、`#`、`;`。
- 静态资源旁路：通过 CDN 缓存版本、`.well-known` 反向确认、备份/临时文件后缀（`.bak` `.old` `~`）探测同一路径的历史版本。
- 只验证「是否仍可达该信息」，不因绕过成功而扩大探测范围或下载完整内容。

## 检测方法

### 1. 错误页面触发
```bash
# 触发 500 错误，观察是否泄露堆栈
curl "http://target/api/user?id=abc'"        # 非预期输入
curl "http://target/api/user?id[]=1"          # 类型混淆
```

### 2. 备份/敏感文件探测
```bash
curl "http://target/.git/config"              # Git 泄露
curl "http://target/.env"                     # 环境变量
curl "http://target/config.php.bak"           # 备份文件
curl "http://target/index.php~"               # 编辑器临时文件
```

### 3. 响应头分析
```bash
curl -I "http://target/" | grep -iE "server|x-powered-by|x-aspnet"
```

**判断依据**：
- 响应含 `root:` / `DB_PASSWORD` / `BEGIN RSA` → 严重泄露
- `.git/config` 返回 200 且含 `[core]` → 源码可下载
- 错误页含绝对路径 `/var/www/...` → 信息泄露

## 工具

| 工具 | 用途 |
|---|---|
| curl | 手工探测敏感路径 |
| dirsearch / ffuf | 批量目录扫描 |
| git-dumper | .git 泄露利用（仅授权） |

## 证据要求

什么才算确认信息泄露（缺一不可）：

1. **可复现**：同一路径/参数重复访问（≥3 次）稳定返回相同的非公开信息。
2. **非公开性确证**：说明该信息为何不应公开（凭证/内网拓扑/源码逻辑/未发布功能），而非常规可公开的版本号。
3. **可达性确认**：明确记录访问所需的身份级别（匿名/低权限），已登录高权限下才可见的按访问控制问题处理，不计入本类。
4. **影响说明**：基于实际观察到的信息内容说明可能的后续利用方向（如内网地址可用于后续 SSRF 目标枚举），不臆测未验证的关联。
5. **证据脱敏**：泄露内容只记录结构与类型（如「发现 3 个内网 IP」），真实凭证/密钥只存哈希，不落明文。

## 输出格式

```json
{
  "finding_id": "info-disclosure-001",
  "issue_type": "info-disclosure",
  "severity": "medium",
  "endpoint": "/.env",
  "evidence": "返回 200，含 DB_PASSWORD=***",
  "remediation": "禁止 Web 访问敏感文件，关闭详细错误，移除响应头版本信息"
}
```

## 禁止事项

- **只读原则**：仅探测是否可访问，不下载/利用泄露内容
- **零触网**：测试用 mock 或本地环境
