## 任务 1 ·【Claude 主力工程师】校验 Agent 执行层 — 独立 session 的 FindingValidator(架构级)

- **分支**:`core/2026-08-06-validator-agent`
- **目标**:ROADMAP Phase 2「校验 Agent 分离 + 4 状态结构化输出」的执行层。Day 3 已落地 findings.py 数据模型,今天把"发现者≠校验者"跑通:校验必须用**独立 SDKExecutor session**(防止自证,DESIGN §3.3),产出过规则表的最终定级。
- **改动范围**(只允许动这些):
  - 新建 `src/cain_agent/validator.py`
  - 新建 `tests/test_validator.py`
- **功能要求**:
  1. `FindingValidator` 类:构造接收一个**专用** `SDKExecutor` 实例(调用方保证它与发现用 executor 是不同 session;类内断言两者不是同一对象,发现同对象直接 raise——防自证是硬约束)。
  2. `async validate(finding: Finding) -> Finding`:把 finding 证据描述发给校验 executor(只读工具白名单,`allowed_tools` 默认空),要求 SDK 侧用结构化输出回 4 状态之一;解析失败/超时 → `validation_system_error`;证据不足 → `validation_inconclusive`,不得猜。
  3. 定级收口:模型回的 severity 只是建议,必须再过 `findings.classify` 规则表,最终 severity 以规则表输出为准(无命中按 Day 3 的降级取低规则)。
  4. 校验结果回写:`validate` 返回的新 Finding 的 `reason` 字段由校验方填写(≤30 字,超长截断并标记),`evidence_hash` 不变(证据同源)。
  5. prompt 构造时把 finding 内容标注为 `[UNTRUSTED_DATA]`(DESIGN §3.2 数据信任边界,防证据里的注入内容指挥校验 Agent)。
- **自测**:fake executor 注入(mock query 返回),零 token 零触网。覆盖:同 session 拒绝、四状态映射、SDK 返回乱码→system_error、定级被规则表压住(模型建议 critical 但规则表说 high → 最终 high)、reason 超长处理。
- **不做**:不接 Orchestrator 流水线(下一任务组装)、不实现真实证据复检工具。

## 任务 2 ·【Codex-A】阿里云 RAM 提权路径分析模块(只读)

- **分支**:`feat/2026-08-06-aliyun-ram-privesc`
- **目标**:ROADMAP Phase 2「云模块:RAM 提权路径分析」。基于 RhinoSecurity 公开研究的 AWS 21 法的阿里云 RAM 等价法,做只读的提权路径检测——全网空白差异化模块的第二个件。
- **改动范围**(只允许动这些):
  - 新建 `src/cain_agent/cloud/aliyun_ram.py`
  - 新建 `tests/test_aliyun_ram.py`
  - `pyproject.toml` 仅允许追加阿里云 RAM SDK 依赖(`alibabacloud-ram20150501` 或直接用 oss2 同款凭证体系+requests 签名,选型自决并在汇报中说明理由;其他不动)
- **功能要求**:
  1. `RamPrivescAnalyzer` 类:凭证只从参数/环境变量读,严禁硬编码落盘;只用 RAM **只读** API(ListUsers / ListPoliciesForUser / GetPolicy / ListPoliciesForRole 等,全部 Get/List 开头)。
  2. 提权路径规则表(代码常量,素材来自公开研究):至少覆盖 5 条 RAM 等价提权路径——PassRole 类(`ram:PassRole` + 可创建函数/实例 → 借高权角色)、AttachPolicyToUser/Group/Role(给自己或可控实体挂高权策略)、CreateAccessKey(给高权用户建 AK)、CreateLoginProfile/UpdateLoginProfile(控制台登录劫持)、AssumeRole 链(可被可控实体 Assume 的高权 Role)。每条规则:`rule_id / 所需权限组合 / 风险描述 / severity`。
  3. `analyze() -> list[RamFinding]`:枚举用户/角色及其策略,与规则表匹配,命中即产出 finding(字段对齐 Day 3 `Finding` 模型可直接转换:cloud=aliyun, service=ram, resource=<用户/角色 ARN>, issue_type=<rule_id>)。
  4. 单实体查询失败容错(权限不足跳过并记录),策略 Document 解析失败不炸全局。
- **自测**:全 mock(mock RAM API 返回构造好的策略 JSON),零触网零真实凭证。覆盖:5 条规则各命中一次、通配 `*` Action/Resource 策略的判定、无权用户容错、`ram:*` 管理员直接标 critical。
- **不做**:不做自动利用/验证性提权(检测只读,利用是红线)、不接 validator、不覆盖腾讯云。
