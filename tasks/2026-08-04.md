- **分支**:`feat/2026-08-04-aliyun-oss-exposure`
- **目标**:ROADMAP「云模块起步:阿里云 OSS 暴露检测」——全网空白的差异化演示的第一步。给定 OSS bucket(或经 aliyun CLI 枚举),只读检查其 ACL/Policy 是否公开可读写,输出结构化 finding。
- **改动范围**(只允许动这些):
  - 新建 `src/cain_agent/cloud/__init__.py`、`src/cain_agent/cloud/aliyun_oss.py`
  - 新建 `tests/test_aliyun_oss.py`
  - `pyproject.toml` 仅允许追加 `oss2` 依赖(阿里云官方 OSS SDK,只读用法;其他不动)
- **功能要求**:
  1. `OssExposureChecker` 类:构造接收 access_key_id/secret(只从参数或环境变量读,**严禁**硬编码或落盘明文;docstring 注明建议 RAM 只读子账号)。
  2. `list_buckets() -> list[str]`:枚举账号下所有 bucket 名。
  3. `check_bucket(name: str) -> OssFinding`:读取 bucket ACL 与 Policy,判定 `public-read` / `public-read-write` / 含 `*`  principal 的 Policy 为暴露;返回结构化 finding:`bucket / region / exposure_level(public_read|public_read_write|policy_public|private) / severity(high|critical|info) / evidence`(证据只记录 ACL 值与 Policy 的 sid/effect,不落敏感内容)。
  4. 定级规则写死在代码里(不靠模型):`public-read-write` 或 policy 公开可写 = critical;`public-read` 或 policy 公开读 = high;private = info。对照 DESIGN §3.3 定级规则表思想。
  5. 单 bucket 查询失败(权限不足/不存在)不炸全局,记入 finding 的 `error` 字段继续。
- **自测**:`tests/test_aliyun_oss.py` 全 mock(monkeypatch oss2 调用),**严禁触网、严禁真实凭证**;覆盖:三种 ACL 定级、policy 通配判定、单 bucket 失败容错。
