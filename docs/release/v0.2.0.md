# Cain v0.2.0 Release Notes

## 中文

v0.2.0 将 Cain 从确定性单流水线推进到中心编排与独立验证体系。`cain-agent run`
现在可以在经典路径和编排路径之间切换：Manager 汇总判断，验证池进行多会话表决，
语义记忆提供相似旁证，失败自愈按策略执行 retry、decompose 或 skip，report 阶段
输出包含置信度、共识和依据链的聚合报告。

### 主要更新

- **中心编排链路**：接入 `recon -> test -> report` 全流程，Manager/Solver/验证池/
  语义记忆统一组装；经典 Route A 保留为可回退路径。
- **独立验证与聚合**：同一 finding 由多路独立会话校验并多数表决，Manager 结合
  表决结果、solver 结果和记忆相似度输出 confidence、consensus 与依据链。
- **语义记忆**：finding 与上下文可向量化存储及相似度检索，减少重复扫描并给
  聚合判断提供旁证。
- **失败自愈**：solver 出现连续空结果、超时或解析失败时，编排层可自动重派、
  分解或跳过任务。
- **实战与确定性验证**：授权目标非 dry-run smoke 走通三阶段并保持零越权出网；
  本地 SSTI fixture 稳定产出 finding，验证 `confirmed 3/3` 表决与 `0.894` 置信度
  聚合链路。
- **编排 benchmark**：同一场景集合可对比经典与编排模式的确认率、耗时、token
  消耗和错误数，报告见 `docs/release/bench-orchestrated-2026-08-19.md`。
- **pi 第二执行后端**：`cain-agent run --backend pi` 通过 Node 桥接入执行引擎，
  支持 anthropic、openai、google、deepseek provider 配置；每笔工具调用回 Python
  侧 scope 判决，`allowed_tools=[]` 时不注册任何工具。
- **scope 语义修复**：仅真实网络目标参与判定，本地路径、grep 正则和重定向体
  不再被误判；命令替换仍按不可见文本默认拒绝。

### Benchmark 摘要

| 模式 | finding 确认率 | 已确认/总数 | 总耗时 | token | 错误 |
|---|---:|---:|---:|---:|---:|
| classic | 66.7% | 4/6 | 0.012s | 538 | 0 |
| orchestrated | 66.7% | 4/6 | 0.020s | 1260 | 0 |

该轮使用 3 个离线确定性场景，验证同场景执行、计量和报告路径；编排模式耗时增加
66.7%、token 增加 134.2%，符合多会话独立表决的预期。数值不代表生产性能基线。

## English

Cain v0.2.0 moves from a deterministic single pipeline to central orchestration with
independent verification. `cain-agent run` can now choose between the classic path
and an orchestrated path: a Manager aggregates judgments, a verification pool votes
across independent sessions, semantic memory contributes similar evidence, automatic
recovery handles retry, decomposition, or skipping, and report generation emits
confidence, consensus, and an evidence basis chain.

### Highlights

- **Central orchestration**: Manager, Solver, the verification pool, and semantic
  memory are wired into the full `recon -> test -> report` flow. The classic Route A
  remains available as a fallback.
- **Independent validation and aggregation**: Findings are validated by multiple
  independent sessions with majority voting. The Manager combines solver output,
  verification results, and memory similarity into confidence, consensus, and an
  evidence basis chain.
- **Semantic memory**: Findings and context can be embedded, stored, and retrieved by
  similarity to reduce repeated work and support aggregation.
- **Failure recovery**: Empty results, timeouts, and parsing failures can trigger
  configured retry, decompose, or skip behavior.
- **Practical and deterministic verification**: A non-dry-run authorized-target smoke
  completed all three stages with no out-of-scope network access. A local SSTI fixture
  deterministically produced a finding and exercised a `3/3 confirmed` vote and `0.894`
  aggregated confidence.
- **Orchestration benchmark**: The same scenario set can compare classic and
  orchestrated runs by confirmation rate, wall time, token usage, and error count. See
  `docs/release/bench-orchestrated-2026-08-19.md`.
- **Second `pi` execution backend**: `cain-agent run --backend pi` uses a Node bridge
  and supports anthropic, openai, google, and deepseek providers. Every tool request
  returns to Python for the scope decision, and no tools are registered when
  `allowed_tools=[]`.
- **Scope semantics fixes**: Only real network targets participate in scope decisions.
  Local paths, grep regular expressions, and redirection targets are no longer
  misclassified, while command substitution remains deny-by-default.

### Benchmark Summary

| Mode | Finding confirmation | Confirmed / total | Wall time | Tokens | Errors |
|---|---:|---:|---:|---:|---:|
| classic | 66.7% | 4/6 | 0.012s | 538 | 0 |
| orchestrated | 66.7% | 4/6 | 0.020s | 1260 | 0 |

The comparison used three deterministic offline scenarios to validate execution,
measurement, and reporting across the same scenarios. Orchestrated mode took 66.7%
more wall time and used 134.2% more tokens, consistent with independent multi-session
voting. These figures are not a production performance baseline.
