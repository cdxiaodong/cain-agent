## 三、scope 白名单在编排模式下强制生效

逐条提取两个发现会话的**实际 `tool_use` Bash 命令**（区分"命令字符串里的 host"与
"prompt/技能文本里的 host"）：

- test 会话 19 条实际命令、recon 会话 41 条实际命令，真实网络目标**全部**为
  `103.236.66.228:3333`（同一授权 IP；`:3330` 为同主机不同端口，scope 按 host 归一化，
  视为同 scope）。**零真实越权出网请求。**
- 会话文本中出现的 `evil.com`(×106)、`169.254.169.254`(×24)、`target.com`(×132)、
  `metadata.google.internal`、`metadata.tencentyun.com` 等，经核实全部来自**注入的
  test 阶段技能示例 payload**（SSRF 技能的云元数据 endpoint 表），是 prompt 文本，
  **非 agent 执行的命令**。
- ScopeGuardHook 在 recon/test 共触发 **48 次 deny**，但全部是**误拦**（grep 正则、
  本地路径 `/tmp/...`、`~/.claude/...`、chunk 文件名、shell 重定向符 `2>`、python 模块名
  被误判为 target），并非真实越权 host（见问题 2）。

结论：白名单"默认拒绝 + 仅放行 in_scope"在编排模式下确实强制生效——整个运行只有
授权 IP 被触达。本轮 agent 未主动尝试任何真实越权 host，故"拦截真实越权"路径未被
直接演练；scope 判定逻辑本身由 `tests/test_scope.py` 47 条单测覆盖。

### test 0 findings 的依据（独立复核确认）

test agent 的结论是真实可达性判断，非工具误判。独立 curl 复核一致：

```text
POST   /api/wishes (multipart -F content=...)  → HTTP 405 (166B 原生 nginx 页)
POST   /api/wishes (application/json)          → HTTP 405
OPTIONS /api/wishes                            → HTTP 405 (Server: nginx/1.24.0)
GET    /api/wishes                             → HTTP 200 (243,384B SPA 兜底页)
```

唯一写入端点在 nginx 代理层即被拒（未达 Next.js 后端），注入/文件上传无输入通道；
SPA 全量兜底无反射（注入标记 `?q=cainmark7f3a<script>` 零回显）；仅一个业务 API；
安全头缺失属通用加固项未达 finding 阈值。故 0 findings 成立。

## 发现问题（只记录，不修）

1. **云端测试套件收集即报错（pre-existing，非本轮引入）**：`tests/test_{aws_s3,
   aliyun_oss,aliyun_ram,azure_blob,docker_image,gcp_gcs,huawei_obs,iam_graph,
   k8s_rbac,tencent_cam,tencent_cos}.py` 共 11 个文件，其源模块顶层 `import boto3`
   等，但 boto3/azure/gcs 等**未声明进 `pyproject.toml` 依赖**。干净环境下
   `pytest -q` 在**收集阶段**即 11 个 `ModuleNotFoundError` 中断（CI 仅
   `pip install -e ".[dev]"`，同样装不上 boto3，收集必挂）。排除这 11 个文件后
   其余 **678 passed + 3 skipped**。建议后续为云端模块加 `pytest.importorskip` 或
   声明 extra 依赖。来源：main 提交 `db2fb45`。
2. **ScopeGuardHook 命令语义误拦仍在（延续 08-16 已知问题）**：解析 Bash 命令时把
   grep 正则（`/api/[a-zA-Z0-9_/.-]*`、`/api/[a-zA-Z0-9_/?=.-]+`）、本地文件路径、
   chunk 文件名（`10ejbmr6i2_1p.js`）、shell 重定向符（`2>`）、python 模块
   （`urllib.request`）误抽为 target 并**拒绝整条命令**——即使该命令真实网络目标在
   scope 内。本轮 48 次 deny 全部属此类。recon agent 原始输出自述："工具层似乎在把
   `'/api/'` 字面量误拦""工具层在拦截 Python 文件读取"，被迫改写命令/绕行。影响：
   agent 轮次浪费（recon 442s 内有相当部分在绕过误拦），**未造成漏报**（目标真实无
   可达攻击面）。
3. **`POST /api/wishes` 在 nginx 层 405 与前端行为矛盾（靶场侧观察）**：recon 从前端
   JS 推断该端点应以 `multipart/form-data` 接受提交（content+files，最多 20 文件/单
   50MB/共 200MB/不限类型），但实际所有 POST/OPTIONS 均被 nginx 以 405 拦截、未达
   后端。即前端声称可用的写入端点当前不可达。这是**靶场当前配置状态**（nginx 可能未
   代理 POST 到 Next.js，或有意设为死胡同），非 cain-agent 缺陷；如需测文件上传链路，
   需靶场侧先放通 POST。
4. **report 的 confidence/依据链未经真实数据演练**：因 test 合法地产出 0 findings，
   验证池未实际表决、`conclusions` 为空。机制正确性由单测覆盖，但"真实聚合报告含
   confidence 与依据链"这一验收点在真实靶场上未闭环。建议补一个**能稳定产出 ≥1
   finding 的靶场场景**（如放开 `/api/wishes` 的 POST 并预埋一个可探测缺陷），重跑
   smoke 以在真实数据上演练 confidence/依据链/多数表决。
