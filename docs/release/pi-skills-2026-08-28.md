# pi 后端三阶段技能 prompt 验证（2026-08-28）

## 范围与结论

本轮验证 `SkillLoader` 产出的 recon、test、report 三阶段代表性技能文本，经过
`PiExecutor` 的 Python 到 Node JSON 行协议后是否保持完整，并检查传输层是否出现
异常体积膨胀。结论：pi 后端边界逐字保留 prompt，无截断、无重复注入，UTF-8
中文不会被 `\\uXXXX` 转义放大；无需修改 Node 桥或 Python 拼装实现。

验证在桥进程边界完成，不调用外部模型，不依赖 provider 凭证。这样可把技能加载与
传输格式的回归测试做成确定性测试；模型供应商自身的上下文窗口与计费不属于本次
协议完整性结论。

## 代表性样本

| 阶段 | 代表内容 | 验证点 | 结果 |
|---|---|---|---|
| recon | SQL 查询参数面识别 | 阶段过滤、中文长文本尾部完整 | 通过 |
| test | 文件上传边界检查 | 阶段过滤、中文长文本尾部完整 | 通过 |
| report | 证据链报告方法 | 阶段过滤、中文长文本尾部完整 | 通过 |
| test（真实库） | `skills/web/sqli/SKILL.md` | 完整技能正文及末尾 256 字符可达桥端 | 通过 |

每个三阶段样本把关键正文重复 200 次以扩大截断信号。测试解码 Python 写入桥 stdin
的首条 JSON 请求，断言 `request.prompt == source_prompt`，并限制 JSON 外壳相对 UTF-8
prompt 的增量不超过 512 字节。该上限覆盖 provider、model、工具清单等固定字段，且
能够发现整段重复或 Unicode 转义造成的异常膨胀。

## 加载行为差异

差异来自仓库技能格式与阶段接线，不来自 pi 后端：

- `SkillLoader` 只加载带 YAML frontmatter 且 `phase` 精确匹配的 `SKILL.md`。
- 当前真实 Web 新规范技能均为 `phase: test`；recon 与 report 在真实技能库中零命中时，
  会注入显式的通用方法论降级文本。
- `skills/web/file-upload/SKILL.md` 是旧格式，不带 frontmatter，因此不会被
  `SkillLoader` 注入。此次用等价的 test 阶段代表文本验证文件上传内容的 pi 传输，
  没有擅自改变旧技能的加载语义。
- 经典 report handler 当前运行校验与聚合逻辑，并不调用 `SkillLoader`。本轮 report
  样本验证的是 pi 协议对 report 阶段技能文本的兼容性，不宣称已新增 report 技能接线。

这些行为与其他后端一致。若后续要让旧文件上传技能或真实 report 技能进入运行时，
应先按技能规范补齐元数据并单独接线；不应在 pi 桥内做后端特例。

## 验证命令

```bash
pytest -q tests/test_pi_skill_prompts.py tests/test_pi_executor.py tests/test_handlers.py
```

新增回归位于 `tests/test_pi_skill_prompts.py`。它直接使用 `PiExecutor` 的真实序列化
路径，仅替换桥子进程为确定性协议端点，因此同时覆盖 `SkillLoader.render()`、UTF-8
JSON 编码和 pi 请求封装。
