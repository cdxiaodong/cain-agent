# 技能编写规范（SKILL.md Authoring Guide）

> 适用对象：后续 ~20 项云技能 + Web 技能扩容的统一模板。本规范由 `tests/test_skill_format.py` 强制校验——写完技能跑一次 `pytest tests/test_skill_format.py`，绿了才算达标。
> 版本：v1 · 2026-08-03（随 SQLi/XSS/SSRF 三个首批技能落地）。

## 1. 文件位置

```
skills/<分类>/<技能名>/SKILL.md
```

- 分类：`web/`（Web 技能）、`aws/` `aliyun/` `tencent/` `huawei/` `azure/` `gcp/`（云技能，对齐 DESIGN §3.4）、`common/`（跨场景通用技能）。
- 技能名：小写、连字符分隔、动词或能力名（如 `oss-exposure-audit`、`sqli`）。
- 每个技能一个目录，目录内放 `SKILL.md`（未来如有辅助脚本/样例，同目录存放）。

## 2. 文件结构（固定，不得增删节）

```
---
name: <技能名，与目录名一致>
description: <一句话定位，须含「面向真实授权系统」语义与能力边界>
phase: <recon|test|framework|report>
severity_focus: <high|critical|info|low>
---

# <技能中文名（英文缩写）>

> <一段定位声明：强调实战非 CTF、本技能解决的核心难点>

## 触发条件
## 三层测试模型
### L1 探测
### L2 验证
### L3 绕过
## 证据要求
## 禁止事项
```

- **frontmatter 四字段缺一不可**，测试会逐字段校验。
- **正文四节缺一不可**，`## 触发条件` / `## 三层测试模型` / `## 证据要求` / `## 禁止事项` 必须以二级标题出现。
- `三层测试模型` 下必须含 `### L1 探测` / `### L2 验证` / `### L3 绕过` 三级标题。

## 3. 各节写法要求

- **frontmatter.description**：一句话说清「测什么 + 面向什么系统 + 产出什么」，禁止空泛（如「测试 SQL 注入」）。
- **触发条件**：列举「什么信号表明该测这个漏洞」，对齐侦察产出（`endpoints.json` / `assets.json`）。要可执行——读者据此能判断「现在该不该进这个技能」，而非泛泛而谈。
- **三层测试模型**：核心区分点，对齐 DESIGN §3.1「L1 探测→L2 验证→L3 绕过」。
  - L1：用最小请求量快速排除明显不存在，给「初判假设」。
  - L2：把假设变成可复现、可演示的差异证据，**禁止仅凭响应码/单次现象下结论**。
  - L3：在 WAF/风控/过滤存在时证明仍可达——这是实战与靶场的分水岭，定级上调的依据。
  - 每层给具体思路与方法，不堆 payload 字典、不给「宝宝巴士」式的手把手命令清单。
- **证据要求**：明确「什么才算确认」，列举可复现性、对照基线、数据库/上下文确证、影响说明等硬门槛。
- **禁止事项**：固定覆盖——仅授权目标、不破坏性测试（只读原则）、凭证不落明文（只哈希）、不超 scope 扩张。

## 4. 内容红线（写技能力刻遵守）

1. **实战导向，非 CTF writeup**：讲参数边界、业务语义、WAF 对抗、误报规避，不讲「如何拿 flag」。
2. **不给破坏性 payload**：只读验证足以定级，禁止 `DROP`/`UPDATE`/写文件/执行命令等破坏性或持久化操作指导。
3. **凭证只哈希不落明文**：技能文本与示例证据中，任何 AK/SK/Token/连接串只记类型 + 哈希。
4. **授权为先**：技能默认在 `scope.yaml` 授权范围内运行，ScopeGuardHook 拦截即停。
5. **不雷同**：不同技能正文去骨架后不得完全相同（测试 `test_new_spec_skill_not_identical_to_others` 会检查）。

## 5. 云技能特别要求

- 云元数据检测类技能（如 SSRF 扩展、metadata 相关）：必须覆盖 `169.254.169.254`（AWS/Azure/GCP 通用）与 `100.100.100.200`（阿里云国产云独有），这是本项目云渗透差异化的体现。
- 云模块技能的 `phase` 通常为 `test` 或新增的 `cloud-recon`/`iam`（如扩展 phase 枚举，需同步更新 `tests/test_skill_format.py` 的 `VALID_PHASES`）。
- 定级规则写死在技能描述里（对齐 DESIGN §3.3），不靠模型自评。

## 6. 写完自检清单

- [ ] frontmatter 四字段齐全，`name` 与目录名一致，`phase` 取值合法。
- [ ] 正文四节标题齐全，三层模型三子节齐全。
- [ ] 无 `TODO`/`FIXME`/`待补充`/占位符（测试 `test_new_spec_skill_no_placeholder` 会查）。
- [ ] 与既有技能去骨架后不雷同。
- [ ] `pytest tests/test_skill_format.py` 全绿。
- [ ] 通读一遍：读者据此能「判断何时进入该技能 + 怎么验证 + 什么算证据」，而非只是 payload 罗列。
